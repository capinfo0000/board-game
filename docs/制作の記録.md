# 制作の記録（ノイ NEU Web アプリ）

このドキュメントは、本リポジトリのゲームを **なぜ作ったか／何に悩んだか／どう改善したか／結果どうなったか** を、開発の流れに沿ってまとめたものです。

---

## 1. なぜ作ったか（目的）

- リポジトリの出発点は「**既存のボードゲームを Web もしくはスマホアプリにする**」という依頼。
- 相談の結果、トランプを使った数字カードゲーム **「ノイ（NEU）」** を題材に決定。
  - 古典的なカードゲームで権利的に安心して作れる
  - ルールが明快で、AI 対戦・オンライン対戦とも相性が良い
- 方針：**ブラウザで動く Web アプリ**（PC・スマホ対応）。まず**オフライン（同一端末＋AI）**を完成させ、その後**オンライン対戦**を追加する段階的アプローチ。

---

## 2. 何を作ったか（概要）

React + Vite のシングルページアプリ。サーバー側プログラムは不要（静的サイト）。

- 👥 **2〜7人**（CPU で席を埋め可）
- 📱 **同一端末パス＆プレイ**（覗き見防止つき）
- 🤖 **CPU 対戦**（弱い／普通／強い）
- 🌐 **オンライン対戦**（PeerJS による P2P・ルームコード・サーバー不要）
- ⚖️ **勝敗モード**：ひとり負け／ひとり勝ち
- 🎛 設定：ライフ 1〜3／手札 3〜5 枚
- ✨ 演出：カード・場の合計・特殊カード・バースト・勝敗、効果音、読み上げ

---

## 3. ルールを固めるまで（要件定義）

チャットでの相談を通じて、次のように仕様を確定していった。

- 上限 **101**（超える札しか出せない＝バースト）
- 特殊カードを「数字に効果を載せる」案から、**専用アクションカード**へ方針転換
- 必殺技（全員の手札を回す）→ 後に **指定プレイヤーと手札を交換する「手札こうかん」** へ変更
- カード名称を分かりやすく：**次の人2枚→ダブル**、**指名→ショット**
- 「最後の1人が勝ち」だけでなく **ひとり負けを決める**モードを追加し、**選択制**に
- ライフ・手札枚数・人数を**設定可能**に

最終的なデッキは **全22種 × 各4枚 = 88枚**。

---

## 4. 悩んだこと・つまずき と その解決

### 4-1. 動作確認の手段がない（ヘッドレスブラウザ不可）
- 実行環境のネットワークポリシーで Chromium のダウンロードが**ブロック**され、こちら側でブラウザ操作・スクショができなかった。
- **解決**：
  - ゲームロジックを**純粋関数のエンジン**に分離し、`node --test` で**ユニットテスト**化
  - **AI 同士の全自動対局シミュレーション**（人数 2〜7・モード・ライフ・手札の全組み合わせ＝数百〜数千局）で、クラッシュ・無限ループ・不変条件（合計 0〜101 など）を検証
  - 画面は **Vite の SSR でレンダリング**して実行時エラーを検出
  - 最終的な見た目確認は**ユーザーの実機**で行い、スクショをもらって調整

### 4-2. GitHub Pages のデプロイで連続でつまずいた
公開作業で複数の壁にぶつかった（いずれも設定・権限まわり）。

1. **`Resource not accessible by integration`** … Actions が Pages を作成する権限を持っていなかった
   → リポジトリ設定の **Workflow permissions を「Read and write」** に変更
2. **`enablement: true` でも作成不可** … API 経由の Pages 自動作成が弾かれる
   → ワークフローから enablement を外し、**Settings → Pages の Source を「GitHub Actions」**に手動設定する方式へ
3. **設定ページが 404** … 実は **GitHub に未ログイン**だった（スクショ右上に "Sign in to view logs"）
4. **個人アカウント設定とリポジトリ設定の取り違え** … `github.com/settings/...`（個人）と `github.com/<owner>/<repo>/settings/...`（リポジトリ）の違いを共有して解決
5. アカウントが `yonekura000000`、リポジトリ所有者が `capinfo0000`（本人の別アカウント）という構成も判明

→ 最終的に **デフォルトブランチ `main` へ反映＋設定2か所** で安定公開に成功。

### 4-3. 「手札こうかん」起因の無限ループ（重大バグ）
- 症状：AI 同士のシミュレーションで一部の対局が終了しない（4万手以上ループ）。
- 原因：AI の「手札が詰まったら必殺技」分岐が、**交換相手（targetId）を指定せずに ultimate を返していた**。手札こうかんは相手指定が必須なので、エンジン側で**何もしない（no-op）**になり、同じ手を延々と選び続けていた。
- **解決**：AI が ultimate を返す全経路で**必ず交換相手（手札の多い相手）を付与**するよう修正。全設定の自動対局で**全局正常終了**を確認。

### 4-4. レイアウトの試行錯誤
- カジュアル路線 → **雀魂（ジャンたま）風の上質テーマ（翡翠グリーン×ゴールド）** へ刷新。
- **円卓レイアウト**化。当初アバターが**卓の枠線に重なる**問題 → アバターを**外周リング**、名前・ライフ・カード枚数を**枠の内側**に**放射状で分離配置**して解決。
- 「出した札」が画面左端の相手に重なる → 合計ブロックを**中央にコンパクト化**＆ゲージを縮小して中央寄せ。
- **人数・名前の長さ・ライフ・手札枚数が増えても崩れない**よう、省略表示・クランプ・縮小・**スマホ用メディアクエリ**を追加。

### 4-5. 演出・音まわり
- 効果音は**音声ファイル無し（Web Audio API で生成）**、読み上げは **Web Speech API**。🔊/🔇 で切替・設定保存。
- 読み上げが早送りで途切れる → **読み上げ中はカード操作と CPU の手を一時停止**するロックを実装。

---

## 5. 主なルール調整（プレイ感の改善）

ユーザーのフィードバックで段階的に調整：

- 「ダブル」を受けた番では**ダブルで返せない**（たらい回し防止）
- 2枚出しの番で**特殊カードなら1枚でOK・義務は次の人へ**／数字・±・101 は2枚必要／**2枚出したターンに引けるのは1枚**
- 詰んでも**手札こうかんが残っていれば即負けにせず**、「使う／使わずバースト」を確認
- J/Q/K のカードに **+20/+30/+40 を大きく表示**、特殊カードは**中央を文字だけ**に、マイナスは**半角表記**
- バースト・勝敗を**読み上げ**（「バースト！ ○○の負け！」「○○が手札こうかんを発動。△△と手札こうかんしました」など）
- 手番に **制限時間 30秒＋ラスト5秒（計35秒）**、0で自動進行

## 7. 技術構成

- **フロントエンド**：React 18 + Vite 5
- **ゲームロジック**：`src/game/`（UI からもオンラインのホストからも使える純粋ロジック）
  - `cards.js` … カード定義・デッキ生成（88枚）
  - `engine.js` … ルール・状態遷移（出せる札判定／バースト／ラウンド／勝敗）
  - `ai.js` … CPU 思考（弱い／普通／強い）
- **オンライン**：`src/net/`（PeerJS ラッパー＋手札を秘匿する redact）
- **音・読み上げ**：`src/sound.js`（Web Audio＋Web Speech）
- **UI**：`src/components/`
